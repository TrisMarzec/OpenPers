## 1. Anwesenheitsliste (Monat)

Neue Standardansicht der Zeiterfassung: eine Zeile pro Kalendertag des Monats.

Spalten: Tag · Soll · Beginn · Ende · Pause (Min.) · Ist · Differenz · Ort · Projekt · Hinweise.

- **Inline-Bearbeitung:** Beginn/Ende/Pause/Ort/Projekt direkt in der Zeile; Speichern beim Verlassen der Zeile (blur) oder Enter, ohne Dialog. Tab springt zur nächsten Zelle. Escape verwirft.
- **Schnellaktionen pro Zeile:** „Wie Vortag“ (übernimmt Beginn/Ende/Pause/Ort/Projekt des letzten erfassten Tages), „Leeren“.
- **Kontext je Zeile:** Wochenende/Feiertag gedimmt mit Name, genehmigte Abwesenheit als Stempel (Soll reduziert), heute hervorgehoben, ArbZG-Hinweise als Warnsymbol mit Text.
- **Kopf:** Monatsnavigation, Summen (Soll, Ist, Differenz Monat) und Gleitzeitsaldo bis gestern.
- Tage mit mehreren Stempelungen (Stempeluhr) werden zusammengefasst angezeigt (erster Beginn, letztes Ende, Pause = Lücken + Pausenfeld). Bearbeiten ersetzt sie durch einen Tageseintrag.

### Datenmodell
`attendance_periods` erhält `break_minutes int default 0` (unbezahlte Pause innerhalb eines WORK-Eintrags) und `location text null` (`office` | `remote` | `on_site`).
Ist-Zeit = Σ(WORK Ende − Beginn) − Σ break_minutes. ArbZG-Pausen = Lücken ≥ 15 Min. + break_minutes.

### Automatische Pausenergänzung
Zeiteinstellung `autoDeductBreaks` (Standard: aus). Wenn aktiv und die gesetzliche Mindestpause (30 Min. > 6 h, 45 Min. > 9 h) nicht erreicht ist, wird `break_minutes` beim Speichern auf das Minimum angehoben; die Antwort meldet `breakAdjusted: true` und die UI zeigt den Hinweis.

### API
- `GET /api/v1/attendance/month?personId&month=YYYY-MM` → `{ days: [...], totals: { targetMinutes, workedMinutes, diffMinutes } }`
- `PUT /api/v1/attendance/day` `{ personId?, date, start, end, breakMinutes, location?, projectId?, comment? }` → ersetzt alle WORK/BREAK-Einträge des Tages durch einen Eintrag
- `DELETE /api/v1/attendance/day?personId&date`

## 2. Organigramm

Seite `/org` (für alle angemeldeten Nutzer, Daten aus dem Verzeichnis):
- **Ansicht „Berichtslinien“:** Baum nach Vorgesetzten; Karte mit Avatar, Name, Position, Team; Anzahl direkter Berichte; auf-/zuklappbar; Wurzeln = Personen ohne (gültige) Vorgesetzte; Zyklen werden aufgebrochen.
- **Ansicht „Abteilungen“:** Baum der Org-Einheiten mit Leitung und Mitgliedern.
- Suche hebt Treffer hervor und klappt den Pfad auf. Klick auf eine Person öffnet das Profil, sofern berechtigt.
- Baumaufbau als reine Funktion in `packages/shared` (`buildReportingTree`, `buildUnitTree`) mit Tests.

## 3. Dark Mode

- Dark ist Standard. Umschalter Hell/Dunkel/System in der Seitenleiste und auf Login/Setup; Auswahl im Browser gespeichert.
- Umsetzung über dieselben Farbtoken (`--color-*`), überschrieben unter `[data-theme="dark"]`; Stempelfarben werden für dunklen Grund aufgehellt (Kontrast ≥ 4.5:1 für Text).
- Karrierseite bleibt hell (öffentliche Außendarstellung), folgt aber `prefers-color-scheme`, wenn der Besucher Dunkel bevorzugt.
