# OpenPers v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native, chosen autonomously per user instruction "arbeite im self loop weiter ohne nachzufragen"). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Self-hostable HR tool with employee records, absences, time tracking, documents, recruiting.

**Architecture:** npm-workspace monorepo; Fastify API with module folders and a shared Zod/domain package; React SPA served by the API in production; Drizzle ORM on PostgreSQL or embedded PGlite.

**Tech Stack:** Node ≥ 22, TypeScript 5, Fastify 5, Drizzle ORM, PGlite / pg, @node-rs/argon2, Zod, Vitest, React 19, Vite, React Router 7, TanStack Query 5, Tailwind 4, i18next.

**Spec:** `docs/superpowers/specs/2026-10-14-openpers-design.md`

## Global Constraints

- Clean-room: no Personio code, names, logos or UI copy.
- Single-tenant; exactly one `company` row created by setup wizard.
- All writes: one transaction incl. `audit_log` row and `outbox` event.
- Writes require header `X-Requested-With: openpers` (CSRF) when cookie-authenticated.
- Errors as `application/problem+json`; 422 validation, 403 forbidden, 404, 409 conflict.
- UI strings only via i18next (`de` default, `en`).
- Sensitive attribute values encrypted AES-256-GCM with key derived from `SECRET_KEY`.
- License AGPL-3.0.

## Review Focus

1. Absence spanning year boundary / holidays / part-time schedule → breakdown counts only scheduled, non-holiday days, split per year for balances.
2. Overlapping absence request for same person → 409, not a silent duplicate.
3. Manager with `reports` scope reading a non-report person → 403 (no data leak in list endpoints either).
4. Clock-in while an open attendance period exists → 409; clock-out without open period → 409.
5. Document download by employee for a non-`employee_visible` document → 403; path traversal in file keys impossible (keys are sha256).
